# AI 接手指南

4. `docs/completed-tasks/` - 已完成任务
5. 本文件

## 项目简介

基于 WebSocket 的远程控制框架。

| 模块 | 说明 |
|------|------|
| `client/` | 被控端 |
| `server_api/` | 核心 WebSocket + HTTP API |
| `server_web/` | Web 控制端 |
| `server_cli/` | CLI 交互式控制端 |
| `shared/` | 共享协议和工具 |

## 功能如何实现
### 全局规范

- 这是远程控制软件，用户如果连接到被控者的客户端，**不应当对用户的操作进行限制**。
- 请先*详细的输出你准备如何完成这个需求*，包括技术方案、实现步骤、可能遇到的问题等，*不要先改代码*
- 先把原始代码*备份*（改为用`git`更优雅的提交备份）
- 在完成后，请用*`golangci-lint run`检查并修复*代码
- 在所有完成后，请写入`docs/completed-tasks/`中
- 请在执行过程中，*保持代码的可读性，可维护性，可扩展性，可测试性，安全性（客户端与服务端的通讯不用考虑，但其他的都必须考虑），健壮性等*
- 要考虑跨平台（如Windows, Linux, MACOS）以及异平台和同平台的通讯
- 请在执行过程中，*保持代码的简洁性*，避免重复代码和冗余逻辑
- 如果可以，最好手动运行程序在UI级别进行*模拟用户的操作/网络请求测试*。
- 如果遇到大量/大段代码要进行复制粘贴或类似提取动作，*不要手动敲*，要通过命令行工具进行复制粘贴（如`sed -n`），但*不要滥用*，然后检查代码是否符合规范。
- 其他工程应有的规范
- 如果要新增用户提示信息，不要直接新增，应通过语言资源文件新增。
- 在构建包的时候，要么只确认编译成功，要么把他打包到/tmp目录上，*不要打包到这个项目内*

### 如果遇到要完成需求，请注意以下事项：

- *异常处理要完整*，不能忽略 error（测试中可用 `_ =` 显式忽略），详见 `docs/dev-rules/001_development_guide.md` 第 2.6 节
- 请在实现过程中，保持代码的可测试性，*编写单元测试*
- 请在实现过程中，*反复检查代码*是否有潜在的bug或逻辑缺陷并修复

### 如果遇到要检查项目规范，请检查代码有没有符合以下规范：

- `main` 函数必须放在文件底部
- 代码是否能在不同的系统上运行
- 从代码的*可读性，可维护性，可扩展性，可测试性，安全性（客户端与服务端的通讯不用考虑，但其他的都必须考虑），健壮性等*角度检查
- 每个函数必须有注释
- 请检查代码是否符合 `docs/dev-rules/` 中的规范
- 请检查代码是否符合 `docs/requirements/` 中的需求
- 通过`go test ./...`检查代码测试是否通过
- 通过`golangci-lint run`检查代码是否符合规范
- 代码是否对*易测试的类或函数进行单元测试*
- 代码有没有*耦合度高，是否符合 SOLID 原则*等
- 代码是否*正确处理错误*，而不是忽略
- 有没有*重复代码或冗余逻辑*
- 代码是否有*潜在的bug或逻辑缺陷*，对较高并发场景的处理是否正确
- 代码是否考虑跨平台（如Windows, Linux, MACOS）以及异平台和同平台的通讯是否正确

### 如果要求要重构，请注意以下事项：

- 首先*展示出重构的详细方案*，包括技术方案、实现步骤、可能遇到的问题等，不要先改代码
- *反复检查*重构逻辑是否完全一致，避免引入新的错误或逻辑缺陷

## 如果要求写文档，请注意以下事项：

- 在看文档的时候，如果有内容与项目规范或进度不一致，需要更新。
- 向用户介绍的文档（*不包含*开发文档，向用户介绍的文档包括*README.md*，*docs/architecture/*）需要是*双语*（中文和英文）
- 在画图表的时候，为了易修改，请使用*Mermaid.js*格式。
